# Session Transcript: Consolidate Agent Hooks Text

## Session Overview
Following stage 017's introduction of a hand-written JS port of Claude Code's hook content, this session found and removed three genuinely duplicated pieces of content across `agent-hooks/`, and merged the `tools/` directory into `agent-hooks/` since its two files existed solely to support it.

## Design Decisions Made

### Decision 1: Consolidate all three duplicated pieces, not just the largest
**Chosen:** Address the `<askfirst-context>` prose, the escalation-reminder wording, and the `askfirst_state_dir()` mangling function (the latter duplicated even within Claude Code's own two bash files) in one stage.
**Rationale:** All three are the same underlying issue; addressing only the largest would leave the smaller ones to drift the same way.
**Proposed by:** git-user

### Decision 2: New canonical source files + generation step, not runtime sharing
**Chosen:** Introduce plain-text/data canonical sources under `agent-hooks/`, spliced by an extended `generate-install-hooks.sh` into the per-tool files at dev time, rather than having installed artifacts load shared files at runtime.
**Rationale:** Installed hook scripts and the opencode plugin must stay single-file/dependency-free at install time (stage 017's own constraint); dev-time generation, already an established pattern from stage 012, extends cleanly without introducing new runtime dependencies.
**Proposed by:** git-user

### Decision 3: No forced code-sharing for the JS mangling port
**Chosen:** The JS port of `askfirst_state_dir()` stays a manually-maintained translation, verified against a shared fixture of input/output pairs rather than a literal shared source.
**Rationale:** Bash and JS cannot execute the same function body; genuine cross-language codegen for a 3-line utility was judged disproportionate.
**Proposed by:** joint

### Decision 4: Merge tools/ into agent-hooks/
**Chosen:** Move `install-agent-hooks.sh`/`generate-install-hooks.sh` from a separate top-level `tools/` directory into `agent-hooks/` itself.
**Rationale:** `tools/` held exactly these two files, both existing solely to support `agent-hooks/` content; the merge also let a redundant second symlink in the R package's `inst/` be removed entirely.
**Proposed by:** git-user

### Decision 5: Keep "hooks" terminology, don't rename
**Chosen:** Considered renaming `agent-hooks/` (and the "hooks"-based public R API) to something mechanism-neutral, given opencode's delivery format is called a "plugin." Decided against it.
**Rationale:** Both Claude Code's hooks and opencode's plugin are, at what they actually implement, hook-shaped (opencode's own SDK types the object every plugin returns as `Hooks`); the term isn't wrong yet, and the blast radius (the whole public R API, not just a directory name) warrants its own dedicated stage if a future tool ever breaks the fit.
**Proposed by:** git-user

## Tradeoffs Considered
- Discovered real (not just accidental) drift in the context prose during consolidation: stage 017's JS version had been deliberately reworded ("PostToolUse hook"/"block" → "tool-execution hook"/"reject") to match opencode's mechanism. Reconciled with genuinely tool-neutral wording ("enforcement hook ... stop ... from succeeding" / "a subsequent failed tool call") accurate for both mechanisms.
