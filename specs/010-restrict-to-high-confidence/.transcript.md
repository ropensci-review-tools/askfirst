# Session Transcript: Restrict to High Confidence

## Session Overview
Design session to restrict all agent-facing signals (load-time notice, error handler, scenario check, capability gap) from firing at medium confidence (no TTY, ambiguous), keeping them gated behind high confidence (known agent detected) only. Medium detection logic preserved for future refinement.

## Design Decisions Made

### Decision 1: High-confidence-only gating for all four signal points
**Chosen:** Replace every `confidence %in% c("high", "medium")` check (or its equivalent) with `identical(confidence, "high")` in `askfirst_init()`, `askfirst_error_handler()`, `askfirst_check_scenarios()`, and `askfirst_capability_gap()`.
**Rationale:** Medium confidence false-positives on non-agent contexts (CI, testing, package installation, R CMD check), creating noise in human workflows. Only high confidence (vendored-data match) reliably indicates an agent caller.
**Tradeoffs:** Medium-confidence sessions (no TTY, no known agent) will no longer see any askfirst signals. This is acceptable because such sessions are more likely human automation than agents.
**Proposed by:** mpadge

### Decision 2: Medium detection logic preserved
**Chosen:** The medium-confidence detection path in `confidence.R` is left entirely unchanged.
**Rationale:** The medium tier remains a valid part of the confidence enum; future work may reintroduce it selectively (e.g. per-package opt-in).
**Proposed by:** agent

### Decision 3: Capability gap also restricted
**Chosen:** `askfirst_capability_gap()` condition changed from `identical(confidence, "low")` (early return) to `!identical(confidence, "high")` (early return).
**Rationale:** Consistency with the other three signal points; capability gaps should only halt agent sessions, not ambiguous non-interactive sessions.
**Proposed by:** agent

## Tradeoffs Considered
- Medium-confidence signalling vs. high-confidence-only: Medium caused noise in CI/installation/testing. High-confidence-only trades slightly reduced agent coverage for dramatically fewer false positives.
- Only init message vs. all four signals: Restricting all four is more consistent and avoids confusion about which signals fire at which tier.
