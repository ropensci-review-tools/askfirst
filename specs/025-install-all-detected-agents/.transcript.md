# Session Transcript: install-all-detected-agents

## Session Overview
mpadge raised a suspicion that the agent-hooks installer would fail when no hooks could be detected at all, and was unsure what happened when multiple agent-specific directories were present. The session redesigned detection/installation to install for every detected tool, fall back to a prompt (or clear error) when none are found, source the tool list from `agent-hooks/manifest.json` instead of hardcoding it, and un-export the R detection helper now that installation handles detection internally.

## Design Decisions Made

### Decision 1: Real opencode auto-detection via a project-level `.opencode/` directory
**Chosen:** `detect_tools()` now treats an existing `.opencode/` directory as "opencode detected," alongside the existing `.claude/settings.json` check for claude.
**Rationale:** opencode's own docs confirm all config locations are read and merged (not first-match-wins), and a project-level `.opencode/` directory is one such location, read regardless of what else exists — a reliable signal, unlike `opencode.json` (which askfirst never reads or writes).
**Tradeoffs:** None significant; this reverses a stage-019 assumption that opencode "has no fixed, project-relative config path," which turned out to be based on an incomplete reading of opencode's precedence docs.
**Proposed by:** joint — mpadge pushed back twice on the agent's initial (incorrect) proposals before the correct signal was identified.

### Decision 2: Splice a generated tool list into the installer, rather than a runtime manifest read or a second hardcoded copy
**Chosen:** `agent-hooks/generate-install-hooks.sh` now splices a `KNOWN_TOOLS` bash array, generated from `agent-hooks/manifest.json`, directly into `install-agent-hooks.sh`.
**Rationale:** The installer must stay self-contained (fetchable standalone via `install.sh`'s curl, with no `manifest.json` alongside it), ruling out a runtime `jq` read; a second hand-maintained hardcoded copy (as `hooks_status.R` already carries) was rejected as exactly the duplication this stage was meant to remove.
**Proposed by:** agent (identified the constraint), mpadge (selected the resolution).

### Decision 3: Un-export the R detection helper
**Chosen:** `askfirst_detect_agent_tool()` is no longer exported; `askfirst_install_agent_hooks()` now detects internally and installs for all detected tools (or prompts/errors), returning a named vector of exit statuses instead of one integer.
**Proposed by:** mpadge.

## Process Notes
Implementation surfaced the actual root cause of mpadge's original suspicion: `detect_tools()`'s `printf '%s\n' "${found[@]}"` emitted one blank line even when `found` was empty (bash always applies a format string at least once), so "zero detected" was indistinguishable from "one match" to every caller. Fixed alongside the planned changes.
