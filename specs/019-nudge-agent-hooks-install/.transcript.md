# Session Transcript: nudge-agent-hooks-install

## Session Overview
Requirements gathering began from a request for agent-directed messaging
when askfirst agent hooks are not installed. This surfaced a documented
stage 014 decision that the existing hooks-install nudge is deliberately
human-directed only. Discussion then expanded into a structural question:
whether the fixed condition/notice text hardcoded in the R binding should
be extracted into a binding-agnostic location before a second language
binding exists.

## Design Decisions Made

### Decision 1: Additive, confidence-gated agent-directed nudge
**Chosen:** A new `askfirst_hooks_nudge` condition, signalled via the
existing `askfirst_signal()` machinery, fires alongside (not instead of)
the unconditional human-directed console nudge, gated on `"high"`
AI-agent confidence, for both `not_installed` and `stale` hook statuses.
**Rationale:** Stage 014's human-directed nudge exists because hook
context can't be relied on to reach an agent; `askfirst_signal()`'s
condition channel has no such dependency and already reaches agents for
other signals.
**Tradeoffs:** Two delivery channels for one underlying event, though
governed by a single once-per-session flag.
**Proposed by:** joint

### Decision 2: New `agent-content/` directory for binding-agnostic fixed text
**Chosen:** Extracted the hard-stop marker delimiters, stop-consequence
text, and notice-prime text out of R string literals into a new
`agent-content/` directory, following `agent-detect-spec/vendor/`'s
sync-copy-and-check pattern (not `agent-hooks/`'s symlink, which cannot
survive packaging outside the monorepo).
**Rationale:** `bindings/r/` is meant to be one of several future
language bindings; fixed condition text a binding runtime emits belongs
with the precedent for binding-consumed canonical content, not
coding-agent-tool hook content.
**Tradeoffs:** Retrofitting existing strings (not just the new hooks-nudge
text) into this stage, rather than deferring, increased this stage's
scope.
**Proposed by:** git-user

### Decision 3: Local pre-commit hook, no remote sync workflow
**Chosen:** A new `.githooks/pre-commit` (opt-in via `core.hooksPath`)
checks both `agent-content/` and the pre-existing `agent-detect-spec/`
vendor sync, backed by a parallel CI check; no scheduled remote sync
workflow, since `agent-content/` is askfirst-authored, not vendored from
upstream.
**Proposed by:** git-user

### Decision 4: Unify marker-token literals with hook-context prose
**Chosen:** `agent-hooks/askfirst-context.txt`'s prose now references
`{{HALT_MARKER}}`/`{{RESUME_MARKER}}` placeholders, rendered by
`generate-install-hooks.sh` from the same `agent-content/` source
`conditions.R` reads at runtime, rather than hand-typing the literal
tokens independently.
**Proposed by:** git-user

## Tradeoffs Considered
- Dev-time R-codegen vs. runtime `system.file()` read for `agent-content/`:
  the latter was chosen, matching the already-established
  `agent-detect-spec/vendor/` precedent rather than inventing a new one.

## Open Questions
- Exact wording of the hooks-nudge message text was finalized during
  implementation rather than left open.
