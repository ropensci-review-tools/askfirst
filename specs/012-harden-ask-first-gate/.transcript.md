# Session Transcript: Harden the Ask-First Gate

## Session Overview
A field report (an agent session with an unrelated adopting package) described askfirst's "ask before implementing a workaround" rule being treated as advisory: the calling agent read the scenario-check message and then offered a workaround as one of two menu options anyway. The session reviewed the report's general recommendations against the current implementation, found two of stage 011's fixes only partial, and hardened the mechanism.

## Design Decisions Made

### Decision 1: `askfirst_check_scenarios()` halts at high confidence
**Chosen:** Signal via `rlang::abort()` (`call_stop = TRUE`), matching the existing `askfirst_capability_gap()` pattern, instead of `rlang::inform()`.
**Rationale:** A message the agent can read and continue past in the same turn does not function as a gate; halting forces an actual stop.
**Tradeoffs:** The function no longer returns a usable value at high confidence — only at medium/low.
**Proposed by:** joint

### Decision 2: `directive:` line differentiated by severity, including `error_redirect`
**Chosen:** `stop-and-ask` for `capability_gap`, `scenario_check`, and `error_redirect`; `notice` only for the load-time notice.
**Rationale:** `error_redirect` always accompanies an already-halting error from the adopting package's own code, so the situation is already a stop even though `askfirst_signal()`'s own call stays non-fatal for that class.
**Proposed by:** joint, with the `error_redirect` inclusion added as an explicit follow-up correction

### Decision 3: Hook guidance drops the workaround-as-menu framing
**Chosen:** On a `stop-and-ask` signal, the hook instructs surfacing the upstream question and waiting for an answer — not presenting a workaround as any kind of option, marked-recommended or otherwise.
**Rationale:** Stage 011's "mark as recommended" mitigation still offered the workaround as a selectable choice, which was identified as the anti-pattern itself.
**Proposed by:** joint

### Decision 4: Installer drift fixed via dev-time generation, not runtime path lookup
**Chosen:** A generation script regenerates the shared installer's embedded hook content from the canonical `agent-hooks/` source at dev time; the installer itself stays self-contained at runtime.
**Rationale:** An initial plan to have the installer resolve `agent-hooks/` via relative filesystem paths at runtime was corrected: `tools/` is shared, language-agnostic infrastructure for all future bindings, and runtime path assumptions would reintroduce exactly the coupling an earlier, deliberate reversion had removed.
**Proposed by:** mpadge

## Open Questions
None outstanding; all three initially open questions were resolved during plan review before implementation began.
