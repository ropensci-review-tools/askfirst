# Session Transcript: Harden Hooks-Nudge Relay

## Session Overview
Starting from a single-session field note (`askfirst-advice.md`) describing
a `hooks_nudge` notice being dropped from an agent's summary when it
co-occurred with a `stop-and-ask` halt, this session designed and
implemented a fix: a dedicated always-relay delimiter for
`askfirst_hooks_nudge`, plus a same-session merge into a following halt.

## Design Decisions Made

### Decision 1: Implement without waiting for multi-trial harness confirmation
**Chosen:** Proceed despite the field note being a single observed instance.
**Rationale:** The fix is low-risk and directly analogous to stage 014's
existing precedent.
**Proposed by:** mpadge

### Decision 2: Scope the new delimiter to `askfirst_hooks_nudge` only
**Chosen:** Not a new general-purpose "must-relay" directive tier.
**Rationale:** It is the only condition class today that is both
non-halting and must-relay-to-a-human, as opposed to must-act-on-by-the-agent.
**Proposed by:** mpadge

### Decision 3: Also implement the nudge/halt merge
**Chosen:** Fold a pending `hooks_nudge` into the next same-session halt as
one message, rather than delimiters alone.
**Proposed by:** mpadge

### Decision 4: No special-casing for `askfirst_error_redirect`
**Chosen:** The merge applies uniformly via the shared hard-stop-shape
branch.
**Rationale:** The nudge fires once, at session outset; error-time signals
fire later, so the pending relay is either already consumed or still
available by construction.
**Proposed by:** mpadge

### Decision 5: Concrete merged-message shape reviewed before coding
**Chosen:** Two back-to-back delimited blocks (nudge, then halt); the
nudge's own trailing `See:` line is dropped when merged, but its
`askfirst::.../type:` header line is kept.
**Proposed by:** mpadge

### Decision 6: Revise the hooks-nudge body wording
**Chosen:** Replace the script-relative-path phrasing with a direct
repository URL ("install 'askfirst' agent hooks from
`https://github.com/ropensci-review-tools/askfirst`").
**Proposed by:** mpadge

## Tradeoffs Considered
- Waiting for `askfirst-tests` harness confirmation vs. implementing now:
  chosen to implement now, given low risk and existing precedent.
- Interleaving nudge text inside the halt block vs. two back-to-back
  blocks: chose the latter for clearer separation of two distinct
  instructions.
