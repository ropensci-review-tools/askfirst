# Session Transcript: revise-messaging

## Session Overview
Designed and implemented a new messaging system for askfirst that replaces the prompt-injection-vulnerable second-person condition messages with a structured `askfirst::<language>::<pkg>::<type>` prefix format, supported by pre-configured agent-tool hooks and a shared installation script.

## Design Decisions Made

### Decision 1: Structured prefix format
**Chosen:** All askfirst condition signals now carry `askfirst::<language>::<pkg>::<type>` as the first line, followed by the message body and a `See: <url>` line. The language component (e.g. `r`, `python`, `rust`) distinguishes bindings.
**Rationale:** AI assistants can recognise this as a legitimate, structured signal rather than a prompt injection. The prefix lets agent-tool hooks pre-load context about what `askfirst::` means.
**Tradeoffs:** Adds verbosity to every signal; the URL is a placeholder until pkgdown docs are live.
**Proposed by:** joint

### Decision 2: Shared agent hooks at repo root
**Chosen:** Hook scripts live at `agent-hooks/claude/` and `agent-hooks/opencode/` at the repo root, shared across all language bindings via symlinks from each `inst/` directory.
**Rationale:** Hooks are language-agnostic and should be consumed by any binding (R, Python, Rust). A single source of truth avoids drift between copies.
**Tradeoffs:** Symlinks in `inst/` may require special handling during R CMD build; confirmed working for this stage.
**Proposed by:** agent

### Decision 3: Shared shell script for hook installation
**Chosen:** `tools/install-agent-hooks.sh` is a standalone shell script callable from any binding. The R function `askfirst_install_agent_hooks()` is a thin wrapper around it.
**Rationale:** Hook installation involves file operations and JSON manipulation best done in shell. A shared script avoids duplicating installation logic across bindings.
**Tradeoffs:** Requires `jq` for automatic settings.json registration; warns if unavailable.
**Proposed by:** mpadge

### Decision 4: Neutral message framing
**Chosen:** Removed all second-person address ("If you are an AI coding agent...", "ask your user") from both the generic notice text and scenario-check messages, replacing with factual framing.
**Rationale:** The structured prefix now identifies the message as agent-directed; the body content should describe the capability rather than issue embedded instructions, which triggered prompt-injection detection.
**Tradeoffs:** Marginal loss of directness; messages become slightly more formal.
**Proposed by:** joint

## Tradeoffs Considered
- R-only installation function vs shared shell script: shell script chosen for binding-agnostic reuse, R function becomes a thin wrapper
- Single agent-hooks directory vs per-binding copies: root-level shared directory chosen with symlinks
- jq dependency for settings.json updates: accepted with fallback warning
