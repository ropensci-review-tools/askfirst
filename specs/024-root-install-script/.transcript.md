# Session Transcript: root-install-script

## Session Overview
Building on an already-approved plan for a root-level `install.sh` wrapper and README/vignette updates, mpadge requested two mid-flight scope additions before implementation: a PowerShell-runnable Windows entry point, and moving the new install-verification test script into a dedicated top-level `tests/` directory rather than colocating it with `agent-hooks/`.

## Design Decisions Made

### Decision 1: Add `install.ps1` as a PowerShell wrapper, not a native reimplementation
**Chosen:** `install.ps1` downloads the same canonical `agent-hooks/install-agent-hooks.sh` and shells it out through a located `bash` (Git Bash, falling back to WSL), rather than reimplementing installer logic natively in PowerShell.
**Rationale:** Keeps a single source of truth for installer logic, consistent with the existing decision (from the base plan) to reject a duplicated/synced copy of the installer for `install.sh`. A native reimplementation would have required extending `agent-hooks/generate-install-hooks.sh`'s sync pipeline with a new target.
**Tradeoffs:** Still requires Git Bash or WSL to be present on the Windows machine; removes the need for the *user* to invoke bash themselves, not the underlying bash dependency.
**Proposed by:** joint — mpadge requested the PowerShell-runnable capability; the agent proposed two implementation approaches (wrapper-around-bash vs. native reimplementation) and mpadge selected the wrapper approach.

### Decision 2: New top-level `tests/` directory for install verification
**Chosen:** `tests/test-install-hooks.sh`, establishing `tests/` as the project's general test location going forward, rather than colocating with `agent-hooks/` (the base plan's original choice, mirroring `askfirst-plugin.test.js`'s colocation convention).
**Rationale:** More tests are expected to land in this location later.
**Tradeoffs:** Breaks from the one existing colocation precedent for this repo's non-R-package tests.
**Proposed by:** git-user (mpadge).

## Tradeoffs Considered
- Native PowerShell reimplementation vs. bash-shelling wrapper: wrapper won to avoid a second synced copy of installer logic.
