# Session Transcript: implement-r-package

## Session Overview
This session designed and implemented the `pkghooks` R package itself, at
`r/` in this monorepo, turning stages 001–002's design output into real
code: LLM-caller detection, confidence tiering, and all three intervention
points (load-time, error-time, capability-gap-time).

## Design Decisions Made

### Decision 1: Vendor a synced copy into r/inst/
**Chosen:** Root `agent-detect-spec/vendor/` stays the source of truth; a
copy is committed at `r/inst/agent-detect-spec/`, kept in sync by
extending the existing `sync-agent-detect-spec.yml` Action and a local
drift-check script.
**Rationale:** Makes the R package self-contained and installable
independently of this monorepo (CRAN, a release tarball, or a standalone
checkout of `r/`).
**Tradeoffs:** Two copies of the same data to keep in sync, mitigated by
automation rather than manual discipline.
**Proposed by:** mpadge

### Decision 2: Global detection cache, but explicit per-package attribution
**Chosen:** The LLM-detection/confidence result is computed once per
session and shared across every adopting package, but every hook
(`pkghooks_init()`'s notice, `on_error` wrapping, `flag_capability_gap()`)
explicitly names the triggering package via a `pkg` argument, stored as a
real field on the signalled condition object.
**Rationale:** Avoids redundant re-detection while still producing
attributable messages in sessions where multiple packages have adopted
`pkghooks`.
**Tradeoffs:** `flag_capability_gap()`'s signature diverges from stage
001's original sketch (which omitted `pkg`).
**Proposed by:** mpadge

### Decision 3: cli/glue-style message interpolation throughout
**Chosen:** All hook message text uses `cli`-style `{}` interpolation
(`cli::format_inline()`), rendered before being attached to the signalled
condition.
**Rationale:** Matches standard modern R package conventions; requested
directly.
**Proposed by:** mpadge

### Decision 4: options(error = ...) instead of globalCallingHandlers()
**Chosen:** Error-time wrapping uses `options(error = ...)`, not
`globalCallingHandlers()` as originally planned.
**Rationale:** Discovered during implementation: `globalCallingHandlers()`
raises "should not be called with handlers on the stack" when invoked from
inside `.onLoad()`/`.onAttach()`, because R's own `loadNamespace()`/
`attachNamespace()` wrap those hooks in a handler context of their own —
confirmed via an actual `R CMD INSTALL` failure, not just a hypothesis.
`options(error = ...)` has no such restriction and was verified to work via
a full install/load/uncaught-error cycle. Both mechanisms share the same
underlying limitation (only fire for errors that propagate uncaught to the
top level), so nothing was given up by switching.
**Tradeoffs:** None beyond the shared, already-accepted top-level-only
limitation.
**Proposed by:** agent

## Tradeoffs Considered
- `globalCallingHandlers()` vs. `options(error = ...)`: the former looked
  more idiomatic for a global calling handler but is unusable from package
  load hooks; the latter has no such restriction and provides equivalent
  coverage.
