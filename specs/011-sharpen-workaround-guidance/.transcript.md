# Session Transcript: sharpen-workaround-guidance

## Session Overview
Triggered by a field-feedback document describing a real failure: an agent hit both the load-time notice and an explicit scenario_check call, but because the task didn't literally match a registered example scenario, it treated the "ask before workaround" rule as soft and offered the workaround as a co-equal option. The session designed a fix that strengthens this guidance without reversing a prior architectural decision.

## Design Decisions Made

### Decision 1: Preserve and strengthen the stage-007 trust-boundary split
**Chosen:** Keep message text (from an adopting package's own signal call) non-imperative, and push directive-strength behavioral instructions into the pre-loaded, trusted agent-hooks context instead.
**Rationale:** mpadge initially proposed reintroducing imperative phrasing directly into message text, reasoning that stage 007's softer framing predated the agent-hooks infrastructure. The agent checked git history and found hooks and the neutral-framing decision shipped in the same stage 007 commit — the split was a deliberate trust boundary (message text is potentially untrusted/spoofable; hook context is not), not a stopgap. mpadge accepted this correction and the resulting two-layer design.
**Tradeoffs:** Message text alone, without hooks installed, still can't be maximally directive.
**Proposed by:** joint

### Decision 2: Message text gets a structural fix, not a tonal one
**Chosen:** Since hooks are opt-in and message text is the only guaranteed channel, message text still needed a fix — but a structural marker rather than second-person prose.
**Rationale:** Balances the trust-boundary concern against the risk of the directive being silently dropped when hooks aren't installed.
**Proposed by:** agent

### Decision 3: Consolidate duplicated scenario bullets to one location
**Chosen:** Drop the scenario bullet list entirely from the load-time notice; it now appears exactly once, at scenario_check time.
**Rationale:** The load-time notice and the on-demand scenario_check message repeated the same bullets under inconsistent headers, inviting an agent to reconcile/average the two into a softer combined reading.
**Proposed by:** mpadge

### Decision 4: Structural directive field applies uniformly to all four signal types
**Chosen:** The new `directive:` line in the signal prefix block applies to `notice`, `error_redirect`, `scenario_check`, and `capability_gap` alike, including the already-halting `capability_gap`.
**Rationale:** Consistency of the prefix-block format across all signal types, rather than special-casing the ones that merely recommend.
**Proposed by:** mpadge

## Tradeoffs Considered
- Reintroducing imperative prose directly in message text vs. routing directive strength through agent-hooks: the latter won because it respects the existing untrusted/trusted split established in stage 007.
